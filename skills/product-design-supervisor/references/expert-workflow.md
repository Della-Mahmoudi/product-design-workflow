# Expert workflow — conditional guidance

Approved conditional guidance for the Supervisor. This is a reviewed-reference approach, not model training, automatic memory or authority to rewrite the plugin.

## Scope

Use only the applicable section. Apply the existing Supervisor core for PD-B01–PD-B09; do not create a parallel core. Preserve the current brief, accepted decisions, designer taste, binding domain standards and actual permissions. This reference grants no new actions or spending. Existing result checkpoints remain: report the result and your technical assessment, then let the Human decide what happens next. Do not send this reference, learning logs or personal preferences to independent Final QA; its existing scope-only contract remains unchanged.

## PD-C01 — Logic-dependent UX

When a current UX decision depends on an unknown backend, AI, payment or permission capability, identify that dependency before presenting the decision as settled. Use available, relevant evidence; mark unresolved assumptions. Ask for a consequential missing Human decision only when it blocks the affected work. Do not impose a developer meeting, investigate unrelated implementation details or stop independent exploration by default.

## PD-C02 — Exploration and convergence

When alternative directions are requested, make the alternatives meaningfully different; do not merge them prematurely or present a preference as proven superiority. Give a reasoned recommendation when useful; testing is not a prerequisite for giving an opinion, and the Human chooses. Match fidelity to the brief: low-fi must communicate the required logic and states, not final polish. After selection, continue that direction without reopening accepted choices unless new evidence or Human direction warrants it. No fixed option count, prototype requirement or additional checkpoint is introduced.

## PD-C03 — Semantic design-system migration

For migration, swap or rebind work, verify the relevant semantic role, actual source and required states or overrides; similar names or appearance alone do not establish equivalence. Preserve appearance and manual work when the brief requires it; this is not a general prohibition on redesign. Justify semantic layers from real usage, not shade counts. Scope inspection to the acceptance criteria, reuse still-valid evidence and disclose inaccessible or unchecked properties instead of claiming completion.

## Maintenance boundary

These are scoped heuristics derived from expert-history reports, not proof of superior outcomes. Do not update this file or learn new global rules during ordinary design work. The owner maintains versioned, reviewed changes outside the execution workflow. Personal language or visual preferences are not shared team defaults.
